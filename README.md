# StudyFlow

跨平台桌面学习管理软件，采用 Wails 3、Vue 3、TypeScript、Vite 和 Go，使用 SQLite 保存本地数据。

## 目录

- `desktop/`：保留 Wails 入口、应用生命周期、提醒调度与对前端的 API 适配。
- `internal/modules/`：按学习项目、计划、学习记录、活动、阶段目标、复盘、设置等业务领域组织 Go 代码。
- `internal/infrastructure/`：SQLite 初始化、存储、日志、提示音、系统集成和 HTTP 响应等底层能力。
- `vue/src/App.vue`：应用外壳，只负责装配组件。
- `vue/src/stores/`：Pinia 领域状态，按页面、设置、项目、计划、学习记录、活动、目标、复盘、统计分别持有数据与操作。
- `vue/src/features/`：按业务模块存放页面与专属弹窗；应用级提醒弹窗（任务、活动、休息、每日复习）也归对应模块，在根组件挂载。`useLifecycle.ts` 统一注册全局事件与定时器，`useBootstrap.ts` 负责启动加载与页面切换。
- `vue/src/shared/`：跨功能使用的格式化工具。
- `resources/Icon.png`、`vue/public/app-icon.png`：应用和托盘图标源文件。`internal/infrastructure/reminder/assets/`：原始铃声的唯一维护位置，由提醒包直接嵌入。
- `build/`：各平台构建配置；`tools/syncassets/`：同步 Go 嵌入资源；`bin/`：构建产物。

`desktop/assets/` 和 `desktop/ui/` 均由构建步骤生成，不要直接修改。

## 开发

```sh
wails3 dev
```

直接运行 Go 程序前，先生成绑定并构建前端：

```sh
go run ./tools/syncassets
wails3 generate bindings -d vue/bindings -ts -i ./desktop
npm --prefix vue install
npm --prefix vue run build
go run ./tools/syncassets
go run ./desktop
```

桌面开发模式使用已安装的 Wails 3 CLI（`wails3 dev`）。构建桌面程序：

```sh
wails3 task build
```

每次执行 `wails3 task build` 或 `wails3 task package`，构建流程仅递增版本号的 D 段，保留 A.B.C。`vue/package.json` 是版本号来源；构建时同步锁文件、Wails 配置、Linux 包版本和 Windows 文件版本。

Linux 可执行文件保留 `bin/StudyFlow` 运行入口，同时输出 `bin/StudyFlow-A.B.C-D-linux-amd64`（架构随构建参数变化）。完整安装包使用 `wails3 task package`，文件名同样包含版本、平台和架构；新产物生成成功后清理同平台、同架构的旧版本。应用中的版本显示与产物一致。

`desktop/goals.go` 只负责请求解析、依赖组装和业务服务转发。阶段目标的业务校验位于 `internal/modules/goals/service.go`，数据访问接口和 SQLite 实现分别位于该模块的 `repository.go`、`sqlite_repository.go`；模块保持单个 Go Package。

默认存储位置：Windows 为安装目录下的 `data/study.db` 和 `logs/`；Linux 为 `~/.StudyFlow/data/study.db` 和 `~/.StudyFlow/logs/`。错误和崩溃日志按日期保存，默认保留 7 天。可以在“设置 → 数据与备份”中选择其他数据目录；切换目录会迁移数据库。自选目录记录保存在默认存储根目录的 `storage-location.txt` 中。

## 设置

设置页的二级导航第一个是“常规”，包含开机自启动（Linux 写用户 autostart 桌面项、Windows 写当前用户注册表 Run 键）、铃声大小（0–100 滑块，0 为静音，拖动后立即生效）、启动后窗口行为（显示主窗口 / 最小化到托盘）、关闭按钮行为（隐藏到托盘 / 退出应用）和版本号。“应用信息”页已并入常规。

其余分类：数据与备份、日志、重置数据，与此前一致。

在“设置 → 数据与备份”中可以开启自动备份。开启时立即生成一份 SQLite 备份，之后每隔 48 小时备份一次；备份保存在当前数据目录的 `backups/` 下，每份保留 48 小时。切换数据目录时，已有备份一起迁移。

学习项目、学习计划和学习记录的普通删除均为逻辑删除，记录仍留在数据库中；“设置 → 重置数据”会永久清空所选数据表。

学习项目可单独设置排序号：已设置的按序号升序排列，未设置的按创建时间正序排列。只有未删除的计划或学习记录会阻止删除项目。学习计划可填写最多 100 字的备注，在计划管理和今日安排中查看；计划管理列表可按学习项目筛选。

学习计划可以设置休息时长。计划时长表示整个时段，计划学习时长为时段减去休息总时长。多次手动暂停共用同一休息额度；倒计时显示在窗口右侧的可上下拖动圆球中。休息到点后会播放提醒音、发送系统通知并弹出确认框。补充学习记录会检查与已有补充记录和计时记录的时间重叠。

计划可以提前开始。提前开始时倒计时锚定到本时段的真实结束时刻，不会因为提前开始而提前结束；到了计划原定开始时间也不再重复响铃，已有计时记录的计划不会再弹“现在可以开始”。

## 提醒与弹窗调度

提醒分为任务提醒、活动提醒、休息提醒三类。同一时刻只展示一个提醒弹窗，由 `desktop/reminder_gate.go` 统一裁决：

| 当前屏幕 | 新到的提醒 | 处理 |
| --- | --- | --- |
| 没有弹窗 | 任意类型 | 立即弹出，同时响铃、发系统通知、唤醒窗口 |
| 已有活动弹窗 | 活动提醒 | 忽略，不换内容，事后也不补弹 |
| 已有任务/休息弹窗 | 同类型提醒 | 不新开弹窗，只替换弹窗内容，铃声继续，不重复通知 |
| 已有任一弹窗 | 其他类型提醒 | 进入等待队列，等当前弹窗关闭后立即弹出 |

等待队列中同一类型只保留最新一条，并保持其原有位置。当前弹窗关闭（提交或确认）后，队列按先后顺序依次投递。

每日复习优先级最高。检查时间可在“进度追因”设置中调整（时 + 分选择，默认 06:00）：每天到达该时间起检查前一天及更早的未填写总结，关闭窗口时也会先拦下复习。复习弹窗出现时停止铃声并接管屏幕，期间到达的提醒一律进队列，不弹窗也不响铃；复习提交后恢复上述规则，若此时仍有其他弹窗开着，则等它关闭后再继续投递。

“学情追踪”包含“阶段目标”和“进度追因”。阶段目标可设置名称、截止日期和备注；完成的目标可在目标列表中查看并重新开启。

活动记录的时间按提交时刻写入，而不是提醒触发时刻：12:00 触发提醒、13:10 才提交，记录时间就是 13:10，中间不会因为一直不处理而补出多条记录。

活动提醒可设置「跳过休息时段」。开启后，休息期间提醒静默：判定为休息的依据是休息额度而非暂停动作本身——计划配了休息时长且暂停在额度内，算休息；计划没配休息时长时点暂停，不算休息、仍视为在计划中，提醒照常触发；休息额度用完后同样恢复触发。计划之间的空档也算休息，但第一个计划之前与最后一个计划之后不算。

## 学习统计

学习统计以所选日期为基准。概览可切换单日、所在周、所在月，总计划、总实际、完成率和各项目对比始终使用同一范围；趋势图可切换周视图和月视图，柱状图对比每日计划与实际时长，折线追踪每日实际学习时长；未来且尚无记录的日期不绘制折线点。历史计划时长按当前启用的计划推算，修改计划前的安排无法从现有数据库还原。

## 已知限制

学习项目删除保护分别向计划和学习记录模块查询关联数据。两次读取不共享同一个 SQLite 快照，且检查与删除沿用现有非事务流程。并发一致性单独评估。
