# 整库导入与导出

入口为「设置 → 数据与备份 → 数据迁移」。导出使用系统保存对话框，恢复先选文件、显示兼容性预览，再确认替换。

- `.studyflow` 是 ZIP，版本 1 包含 `study.db` 与 `manifest.json`。清单记录包格式版本、数据库版本、导出时间、时区标识及数据库 SHA-256。数据库是应用在独占借用下生成的一致性快照。打包在数据库锁外完成，完整写入后发布为新文件。
- 旧版 `study.db` 先通过 SQLite 只读复制获得一致性快照，再和备份包走相同的 Goose 检查。新版数据库、未知结构、异常升级历史、损坏包和空数据库拒绝恢复。可识别的旧库在用户确认后升级副本，按当前目标版本复检。清单里的版本必须与实际数据库匹配。
- 本机或导入副本中有未结束的会话时停止。暂停和休息也算未结束。本机计时状态在实际独占恢复前再次检查。未提交表单草稿不参与迁移，已保存的业务数据、关联、删除标记、设置和 Goose 历史随数据库保留。
- 恢复使用 SQLite 的整库页复制事务，保留本机工作库路径。提交前取消或中断由 SQLite 撤销未完成的写入。临时原库用于极端情况下的回滚，成功后清理，不作为第二份工作库或额外常驻备份。正常失败后原库有效。无法确认回滚时暂停数据库访问、报告并保留临时原库路径。
- 原始导入文件、本机存储位置、窗口状态和系统自启动不受恢复影响。设置随库替换，时区差异可能改变按日统计的归属。旧库没有来源时区时在预览中提示。完成后通过正常退出和重新启动重新装载业务，避免旧库后台状态继续运行。

## 验收

- `internal/infrastructure/transfer` 测试整库数据与设置保真、本机唯一工作库、同版本和无账本旧库、超新版本、损坏包、文件名冲突、计时和取消。
- `internal/infrastructure/persistence` 的恢复测试覆盖临时副本生成失败、源损坏、提交后复检失败、回滚结果不确定，以及在已写入回滚日志后取消或强制终止进程。
- `scripts/qa/test-data-transfer-windows.mjs` 使用 Windows 实际窗口验证四个设置面板的内容边距、透明行背景和主题色按钮、导出、取消、替换、清理临时库和重启。使用独立夹具。测试二进制通过 overlay 仅替换系统对话框选中的路径，并开启本地调试端口。这个检查不等于验收原生选文件交互。
- 原生 Linux 实际桌面仍需验证系统文件对话框、设置页外观以及恢复后重开。跨时区不会重写历史时间戳。
