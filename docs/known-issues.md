# 已知问题

## 补录与计时可重复累计

状态：已修复新增重叠记录，Windows 原生交互待验收。

原复现：先补录 10:15–10:45，再计时 10:00–11:00，累计为 90 分钟。现在补录若占用未结束计划的可计时时段，会列出冲突并要求确认；实际记录或运行中计时的保留区间重叠则直接拒绝。启动、恢复计时在同一写入事务内重新检查，允许首尾相接。已存在的记录不回填、不去重。

## 补录错日期后缺少删除入口

状态：暂不处理。

「每日计划与实际」统计明细能查到其他日期的补录，但没有删除入口；当前删除按钮只在「今日计划」。后续可在统计明细中为已结束记录提供删除入口，并在确认时显示日期和时段。本轮暂不改界面。

## 追因历史超过 120 条后无法在界面查看更早记录

状态：暂不处理。

「每日检查结果」只查询最近 120 条，界面没有分页或日期筛选。更早的结果仍保留在数据库里。

## 引入 NTP 时间服务器

状态：暂不处理，下轮讨论和实现。此项是尚未实现的功能，不是已确认的北京时间归档问题。开始实现前先明确用途、对离线使用的影响，以及不可达或时间跳变时的行为。

## 没有学习项目时，下拉框只显示「0」

状态：用户报告，待复测。用空库或没有可用项目的日期分别检查新建计划和补录的项目选择框。预期不显示内部默认值 `0`，而应提示没有可用的学习项目，并在未选到有效项目时禁止保存。

## 下轮工作与验收顺序

1. 验收补录与计时的防重叠修复；其余四项仍待处理：错日期补录缺少删除入口、追因历史仅显示最近 120 条、引入 NTP 时间服务器、没有项目时下拉框显示「0」。
2. 其余功能在 Linux 和 Windows 上先做正常流程验收。正常流程通过后，按每项功能的故障模式补极端场景，不能用单一平台或自动测试结果代替另一平台的原生验证。
3. 极端场景按功能选择：例如进程崩溃或强制结束、休眠和唤醒、系统时间跳变、断网或超时、磁盘写满、目录权限变化。使用隔离库或虚拟机，记录复现步骤、预期结果和实际结果，不对日常数据做故障注入。
