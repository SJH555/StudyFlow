# 手动补录最小时长与来源标签（0.5.0-4）

## 修改

- 手动补录必须至少 10 分钟。弹窗实时显示时长和错误，非法区间禁用保存；store 提交前再次校验，后端在开启事务/写入前拒绝短区间，无法绕过前端保存。
- 今日学习记录及学习统计的“每日计划与实际”使用同一来源标签组件：手动补录（铅笔）或计时学习（计时器）。原计划一侧不添加学习记录来源标签。
- 启动初始化时，仅将 `source=manual`、已结束、时长不足 600 秒的历史记录设为 `deleted=1`，沿用计时学习不足 10 分钟的软删除语义。原始内容仍在数据库中，有效补录和进行中记录不受影响。旧记录不再出现在统计或参与冲突判断。
- 没有修改既有区间冲突判定、计划冲突判定或时间边界规则。

## 验证

- `go test ./internal/...` 全部通过。新增测试覆盖 5 分钟、599 秒、599.999 秒、恰好 600 秒及 601 秒；验证拒绝时不写入，正常记录来源为 manual。
- 历史短记录升级后允许重用其时段，有效记录重叠仍被拒绝；原始记录和备注保留。重复启动清理幂等，600 秒记录、进行中记录及 timer 来源不被该修复误处理。
- `node scripts/qa/test-manual-validation.cjs` 通过：前端非法区间不发送 API 请求，满 10 分钟允许提交，后端冲突后保留弹窗。
- 既有 `node scripts/qa/test-countdown.cjs` 通过。
- Vue 类型检查、Vite 生产构建及 Windows amd64 交叉编译通过。

Windows：

- WSL 编译的 desktop 测试程序在 Windows 运行，6 个手动记录/计划冲突用例通过，退出码 0，见 `windows-api-tests.txt`。覆盖手动/计时记录重叠、最小时长、首尾相接、进行中/暂停时段和已删除记录的原有规则，以及计划星期/编辑冲突。
