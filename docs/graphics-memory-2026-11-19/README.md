# 图形内存隔离实验

## 范围与判定规则

本轮验证图表渲染器能否降低内存，同时保持现有响应速度。正式产品继续使用 Canvas；SVG、无图表和空外壳只存在于显式启用的测试构建中。没有修改数据库、版本号或用户数据。

结论：SVG 路线停在实验阶段，建议不采用。本机三轮中，SVG 的 GPU 进程下降，但渲染进程增加，总私有内存没有下降。它还会改变现有导出格式，没有理由为此引入 PNG 转换代码。没有用不利结果继续推进产品修改。

不能只比较 GPU 进程：SVG 可能把开销转移到渲染进程。采用整个应用进程树的 Private Bytes，分别记录 Go 主进程、WebView 浏览器、GPU、渲染及辅助进程。Working Set 求和可能重复计算共享页，不作为主要结论。GPU 进程私有内存也不等同于显存。

若收益落在波动范围内，或需要以明显延迟、导出功能退化为代价，则不替换现有渲染器。保留此前已验证的离页销毁与数据清理，不为实验强制生产环境 GC，也不关闭硬件加速。

## 方法

- WSL 构建四个 Windows 生产优化二进制，使用相同 Go 代码。测试 overlay 只隔离配置/WebView 目录并开启本地 CDP；正常启动没有这些配置。
- `shell` 仅挂载空前端，Go 启动门禁仍保留；`none` 正常查询与显示统计布局，但不绘制图表；`canvas` 为当前实现；`svg` 仅替换 ECharts 渲染器。
- 空外壳会让未使用的工作区代码被构建器剔除，因此只是粗略基线，不能把它与首页的差额全部认定为可删除内存。
- 每个版本使用独立、带 `.studyflow-qa` 标记的临时数据，均为 365 天、8760 条手动/计划混合记录。当月统计为 456 条、547200 秒。每次启动核对窗口、缩放与统计结果一致。
- Windows WebView2，视口 1380×920 CSS 像素，DPR 1.5。先跑一轮 pilot 排查工具，再跑三轮交叉顺序：shell/none/canvas/svg、svg/canvas/none/shell、none/svg/shell/canvas。
- 首页、首次月统计、连续三次刷新后、离页后分别等待 5 秒采样；另存刷新结束立即采样值。它们不是连续峰值，也不是数小时驻留测试。
- 离页后显式 GC 只用于诊断保留量，放在自然采样之后，不能与自然样本混用。截图和导出探测更晚执行，避免影响前面的样本。
- CDP 检查统计值、图表绑定当前 DOM、离页实例清理和前端异常。PNG 导出探测只核对返回格式，不操作原生保存对话框。

## 三轮结果

下表为中位数，内存单位 MiB。刷新耗时各取三轮共九次，首次进入各取三次；耗时指页面数据和图表初始化就绪，不表示所有动画结束。原始数据在 `comparison/results.json`，摘要在 `comparison/summary.json`；pilot 不纳入此表。

| 场景 | 无图表 | Canvas（现有） | SVG（实验） |
| --- | ---: | ---: | ---: |
| 首页总私有内存 | 298.7 | 303.8 | 301.6 |
| 首次月统计，等待 5 秒 | 325.1 | 359.8 | 369.0 |
| 三次刷新后，立即采样 | 354.8 | 421.3 | 406.7 |
| 三次刷新后，再等待 5 秒 | 337.8 | 386.4 | 405.1 |
| 离页后，等待 5 秒 | 362.0 | 401.2 | 423.7 |
| 诊断用：离页后显式 GC | 335.9 | 358.0 | 355.5 |
| 首次进入统计页 | 233.6 ms | 240.3 ms | 242.6 ms |
| 月统计刷新 | 156.4 ms | 172.1 ms | 170.8 ms |

空外壳总私有内存中位数 233.1 MiB，范围 230.3～235.1 MiB。其中仍包括正常 Go 宿主、数据库准备、Vue/Vuetify 和 WebView，并非纯浏览器成本。

首次统计页中，Canvas 的 GPU/渲染进程中位数分别为 163.1/75.0 MiB，SVG 为 147.7/101.4 MiB。分别取中位数的进程值不应当作同一时刻精确求和。两块 Canvas 的宽×高×4 合计约 5.1 MiB，只代表单份 RGBA 像素估算，不能据此推算浏览器全部缓冲区。

SVG 的首次统计页范围 366.5～369.4 MiB，Canvas 为 354.3～360.9 MiB。SVG 自然离页采样也更高。显式 GC 后差异很小；SVG 虽然在“刷新结束立即采样”更低，但那不是连续峰值，不能选取这一项宣称整体节省。刷新速度接近，未发现值得用导出复杂度换取的内存收益。

三轮共 12 个实例全部完成；非空外壳版本统计值一致，Canvas/SVG 学习趋势序列一致，图表绑定和离页清理检查通过，没有捕获前端运行时异常。实际 Windows 截图在各轮输出目录。Canvas 导出返回 PNG；SVG 即使请求 `type: 'png'` 仍返回 SVG 数据 URL，因此尚不满足现有 PNG 契约。没有实现或声称验证 SVG 的 PNG 转换、HTML 保存或原生保存对话框。

后续若继续优化，应先对真实长期驻留、窗口隐藏后的宿主/WebView 行为做专项验证，再决定是否需要宿主层适配；当前实验不足以证明“引擎占用都不可优化”。本轮没有关闭 GPU、销毁工作区或调整 GC 策略，正常产品保留现有响应和导出行为。

四种实验构建及正常前端恢复构建通过。测试脚本语法、Python 编译和差异空白检查通过；共用 Windows 测试入口增加主程序判断后，以现有 Canvas 二进制单轮单次切页进行 smoke 检查通过，输出见 `harness-smoke/`。本轮只有测试工具和文档新增调整，不重复执行此前已完成的 Go 业务全量回归。

## 工具与复现

```sh
python3 scripts/qa/build-graphics-experiment.py
python3 scripts/qa/prepare-graphics-experiment.py
node scripts/qa/test-graphics-experiment.mjs FIXTURE_ROOT OUTPUT_DIRECTORY
```

构建脚本会临时同步测试前端产物，最后在 `finally` 中重建正常前端并同步；不应同时运行其他构建。需要可用的 Go、Node 和 Windows PowerShell。不要调用会递增版本的发布任务。

测试 Vite 配置是 `vue/vite.graphics-qa.config.ts`，普通构建不读取它。二进制校验和保存在夹具 `graphics.json`，验收副本与结果一起记录。`GRAPHICS_RUNS` 控制轮数，`GRAPHICS_IDLE_MS` 控制自然采样前的等待时间。调试端口被占用时拒绝运行；每个实例在 `finally` 中退出。

工具初测曾因 `Runtime.evaluate` 返回整个 Pinia 对象触发 CDP 序列化深度错误。已改为只赋值、不返回对象，退出测试实例后重新运行；失败尝试没有用于比较产品内存。
