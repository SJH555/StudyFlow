后续统计批量查询优化已完成，当前查询实现与性能请见 [统计查询阶段记录](../stats-query-2026-11-19/README.md)；本页保留前一阶段的验收基线。

## 最终启动方式

| 阶段 | 执行内容 | 边界 |
| --- | --- | --- |
| 必需初始化 | 数据位置与升级检查、常规设置、铃声资源准备 | 保留数据库安全门禁和启动驻留托盘设置 |
| 首页加载 | 设置、科目、计划、今日记录、目标 | 合并重复今日查询，首页不等待活动记录和数据目录 |
| 补充加载 | 复盘检查、活动记录、数据目录 | 复盘可能扫描历史日期，完成这些初始查询后再放行维护 |
| 维护 | 启动器维护、首次到期备份检查、后续定时备份 | 通过一次性就绪信号触发；等待时不借用数据库连接，退出可取消 |

这是函数传参和阶段信号组成的小型协调器，不提供任意依赖图或通用任务调度框架。提醒仍在数据库和资源准备完成后启动，不等待维护任务。隐藏启动时前端同样发布就绪信号，不依赖焦点、定时延迟或可见帧。

铃声内容一致时不再覆盖写入；缺失、损坏或应用资源变化时重新生成。未改变数据库结构、字段含义、SQL 升级版本或应用版本，未执行正式打包。

## Windows 前后对照

使用同一台机器、相同生产优化参数、相同隔离数据（365 天、每天 24 条，共 8760 条学习记录），各启动三次，每次进入统计页三次。对照版由 HEAD b3ceaf2 源码构建，两版加入相同的分段计时。最终只使用 final/windows-performance.json，失败实验不计入结论。

| 指标（中位数） | 修改前 | 修改后 |
| --- | ---: | ---: |
| 启动到首页就绪观测值 | 1022 ms | 930 ms |
| 首次统计页初始化就绪 | 776 ms | 770 ms |
| 再次进入月统计初始化就绪 | 1764 ms | 1768 ms |
| 月统计刷新 | 1713 ms | 1734 ms |
| 首页 JS 堆保留 | 6.11 MiB | 5.39 MiB |
| 离开统计页后 JS 堆保留 | 9.61 MiB | 8.53 MiB |
| 离开统计页后进程树私有内存 | 414.40 MiB | 409.77 MiB |
| 离开统计页后进程树工作集 | 584.60 MiB | 585.37 MiB |
| 前端主 JS 文件 | 1591.93 kB | 1059.83 kB |

这些是小样本观测，不能宣称普遍提升或大幅降低总内存。启动观测包含 PowerShell 启动和调试连接开销，已有 WebView 缓存，最终对照中备份未到期，不是严格冷启动。图表就绪指数据加载和实例初始化完成，不代表动画全部结束。

内存统计包含本次应用进程及其 WebView 后代进程；JS 堆在显式 GC 后采样，反映保留量，不是日常峰值。整个进程树内存变化较小，未将其描述为明显改善。测试版本仅通过编译器 overlay 开启调试端口并隔离配置/浏览器缓存，产品源码没有开启调试端口。

## 已撤回的实验

直接复用 ECharts 实例与当前容器重建生命周期冲突，Windows 截图出现空白；已按用户要求暂停并撤回，用户选择保留重建后继续验证。failed-reuse/ 保存失败现场和原始数据，不能作为验收通过依据。

timing-before-adjustment/ 的刷新刻意与周月切换尚未结束的请求重叠；它显示排队开销，不能用来解释独立刷新。timing-settled/ 改为等待切换结束后测量，最终三轮对照采用相同方法。

## 对照脚本用法

准备两份 Windows 测试二进制后，使用下列入口；二进制仅在测试 overlay 中打开 19349 调试端口，并把配置与 WebView 缓存放在各自测试目录。使用同一套 frontend 分段计时代码记录对照数据。

```sh
python3 scripts/qa/prepare-startup-memory.py \
  --before-binary /path/to/before/StudyFlow.exe \
  --after-binary /path/to/after/StudyFlow.exe \
  --temp-dir /mnt/c/Users/USER/AppData/Local/Temp
node scripts/qa/test-startup-memory-windows.mjs FIXTURE_ROOT OUTPUT_DIRECTORY
```

输出目录须预先创建。默认三轮、每轮三次切页；可用 QA_RUNS、QA_CYCLES 缩小次数。QA_VARIANTS=after QA_FEATURES=1 执行候选版补充功能检查。脚本只接受带 `.studyflow-qa` 标记的夹具目录，不应指向用户数据目录。

原生保存对话框和长时间驻留仍是人工验证边界。稳定计时须先等待周月请求结束；不要把快速切换留下的排队请求记成独立刷新耗时。
